    راهنمای انتشار

    انتشار روی GitHub Pages، گام‌به‌گام

    این ابزار یک فایل HTML ایستا است و بدون سرور روی GitHub Pages اجرا می‌شود. به‌جای USERNAME نام کاربری GitHub خودتان را بگذارید.

    1. ساخت مخزن

      در GitHub روی New repository بزنید، نام promptsaz را بنویسید، گزینه Public را نگه دارید و README نسازید.

    2. آماده‌کردن پوشه و فایل

      فایل HTML این ابزار را با نام index.html داخل یک پوشه‌ی تازه بگذارید و دستورهای زیر را اجرا کنید.

      mkdir promptsaz && cd promptsaz
git init
git add index.html
git commit -m "first version"
git branch -M main

    3. اتصال به GitHub و ارسال

      آدرس مخزن را وصل کنید و فایل‌ها را بفرستید. اگر GitHub CLI نصب دارید، دستور دوم همین کار را یک‌جا انجام می‌دهد.

      git remote add origin https://github.com/USERNAME/promptsaz.git
git push -u origin main
      gh repo create promptsaz --public --source=. --push

    4. فعال‌سازی Pages

      در مخزن به Settings، سپس Pages بروید. در بخش Source گزینه Deploy from a branch را انتخاب کنید، شاخه main و پوشه / (root) را بزنید و Save کنید.

    5. باز کردن سایت

      بعد از یک یا دو دقیقه سایت در این آدرس در دسترس است:

      https://USERNAME.github.io/promptsaz/

    6. به‌روزرسانی‌های بعدی

      بعد از هر تغییر در فایل، این سه دستور نسخه‌ی جدید را منتشر می‌کند.

      git add .
git commit -m "update"
git push

    7. دامنه‌ی اختصاصی و HTTPS

      در همان صفحه Pages، فیلد Custom domain را پر کنید و گزینه Enforce HTTPS را روشن کنید.

      حساب‌ها و صف تأیید در localStorage مرورگر هر بازدیدکننده ذخیره می‌شوند و بین دستگاه‌ها هم‌گام نیستند. برای تیم واقعی چندکاربره به بک‌اند و احراز هویت سمت سرور نیاز دارید.

    ساخت اپلیکیشن اندروید در GitHub

    لازم نیست Android Studio نصب کنید. خروجی اندروید پرامپت‌ساز یک گردش‌کار GitHub Actions دارد و بعد از push، APK را خودش می‌سازد.

    1. گرفتن پروژه‌ی اندروید

      در بخش «صف تأیید»، پرامپتی را که تأیید شده بازکنید، «ساخت خروجی» را بزنید و «دانلود پروژه‌ی اندروید (ZIP)» را بگیرید. فایل ZIP را از حالت فشرده خارج کنید.

    2. ساخت مخزن

      در GitHub یک مخزن تازه بسازید (نوع Private پیشنهاد می‌شود) و README نسازید. بعد در پوشه‌ی بازشده:

      git init
git add .
git commit -m "android app"
git branch -M main
git remote add origin https://github.com/USERNAME/my-android-app.git
git push -u origin main

    3. اجرای گردش‌کار

      به تب Actions مخزن بروید. گردش‌کار «Build Android APK» خودکار اجرا می‌شود و ۳ تا ۶ دقیقه طول می‌کشد. اگر اجرا نشد، آن را انتخاب و Run workflow را بزنید.

    4. دانلود APK

      وقتی اجرا سبز شد، وارد آن شوید. در پایین صفحه بخش Artifacts فایل android-apk را دانلود کنید. APK داخل یک فایل ZIP است.

    5. نسخه‌ی رسمی در Releases

      با ساخت یک تگ، APK خودکار به صفحه‌ی Releases اضافه می‌شود.

      git tag v1.0.0
git push origin v1.0.0

    6. نصب روی گوشی

      فایل APK را به گوشی منتقل کنید و اجازه‌ی نصب از این منبع را بدهید. بدون کلید امضا، APK با امضای آزمایشی (debug) ساخته می‌شود که برای تست خوب است ولی برای فروشگاه‌ها مناسب نیست.

    7. امضای نسخه‌ی نهایی (اختیاری)

      یک keystore بسازید، آن را base64 کنید و در Settings > Secrets and variables > Actions چهار مقدار KEYSTORE_B64، KEYSTORE_PASSWORD، KEY_ALIAS و KEY_PASSWORD را بگذارید. با وجود این‌ها گردش‌کار خودکار نسخه‌ی release امضاشده می‌سازد.

      keytool -genkeypair -v -keystore release.jks -alias app -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 release.jks
      فایل keystore و رمزها را هرگز در مخزن commit نکنید. فایل .gitignore پروژه فایل‌های jks را کنار می‌گذارد، ولی مسئولیت نگه‌داری نسخه‌ی پشتیبان کلید با خودتان است؛ با گم‌شدن آن دیگر نمی‌توانید برنامه را به‌روز کنید.
    مشاهده‌ی فایل گردش‌کار (android.yml)

    اپ اندروید خود پرامپت‌ساز

    بعد از انتشار این ابزار روی GitHub Pages، می‌توانید آن را به‌شکل یک اپ اندروید هم بسازید. آدرس سایت خود را بنویسید تا پروژه‌ی آماده (با همان گردش‌کار ساخت) دانلود شود. برنامه فقط به همان دامنه اجازه‌ی ناوبری می‌دهد و بقیه‌ی پیوندها را در مرورگر باز می‌کند.

    پرامپت‌سازنسخه‌ی نمایشی برای اپراتورها
    داده‌ها فقط در مرورگر همین دستگاه می‌مانند. خروجی‌های ساخته‌شده پروژه‌ی آماده‌ی اجرا هستند، نه فایل نصبی کامپایل‌شده.
